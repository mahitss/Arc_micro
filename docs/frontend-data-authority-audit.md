## 1. Executive Summary & Audit Mandate

The AgentPay system enforces mathematical guarantees: no AI agent holds private keys, all financial mutations pass deterministic policy checks, and no funds move without dual-mode verification. However, prior to this audit, multiple frontend pages and API client wrappers in `apps/web` exhibited a **silent fallback anti-pattern**:
```typescript
// ANTI-PATTERN IDENTIFIED ACROSS API CLIENTS:
try {
  return await apiRequest('/api/resource');
} catch {
  return MOCK_RESOURCE; // Silently masquerading fixture as live state
}
```
This pattern caused simulated or demo fixtures—such as fake balances, fake agent listings, fake transaction hashes, and fake active reservations—to be rendered in normal mode without provenance badges whenever the backend Gateway was offline or responding with an error.

### Strict Data Authority Rules
Every frontend field must belong to exactly one authoritative category:
1. **Category A: `LIVE_BACKEND`** — Authoritative live data from Go Gateway, PostgreSQL read-models, or Arc RPC node.
2. **Category B: `DETERMINISTIC_SIMULATION`** — Pure deterministic simulation state, generated by simulation engines or canonical demo fixtures, explicitly gated and visibly labeled with `SIMULATION — NO FUNDS MOVED` or `DEMO FIXTURE`.
3. **Category C: `STATIC_CONFIGURATION`** — Fixed protocol configuration parameters (e.g., Chain ID 5042, USDC Token address `0x3600...0000`, 7-tier authority hierarchy definitions, Constitution v8 rules).
4. **Category D: `EMPTY/UNAVAILABLE`** — Honest, structured empty/unavailable states (e.g. `NO DATA`, `BACKEND UNAVAILABLE`, `0 VERIFIED TRANSACTIONS`, `AGENTVAULT NOT DEPLOYED`).

**Zero Tolerance Violation:** Never silently convert Category B into Category A, and never fabricate fake transaction hashes, fake balances, or fake live execution state.

## 3. Classification Framework (Phases 2 & 3)

To ensure mathematical and operational integrity across all 79+ routes in `apps/web`, we establish the **Frontend Data Authority Matrix**:

```
+-------------------------------------------------------------------------------+
|                             DATA AUTHORITY MATRIX                             |
+--------------------------+-----------------------+----------------------------+
| Category                 | Allowed in Live Mode? | Provenance Label Required? |
+--------------------------+-----------------------+----------------------------+
| A. LIVE_BACKEND          | YES (Primary)         | LIVE / REAL                |
| B. DETERMINISTIC_SIM     | YES (Gated behind sim)| SIMULATION / PROJECTED     |
| C. STATIC_CONFIGURATION  | YES (Read-only spec)  | PROTOCOL CONFIG (SPEC)     |
| D. EMPTY/UNAVAILABLE     | YES (Honest default)  | UNAVAILABLE / NO DATA      |
+--------------------------+-----------------------+----------------------------+
```

### Inviolable Invariants:
1. **INV-DATA-1:** LIVE mode queries MUST NEVER return mock/simulation fixtures on catch/failure.
2. **INV-DATA-2:** SIMULATION mode queries MUST be explicitly toggled and visibly labeled with `SIMULATION — NO FUNDS MOVED` or `DEMO FIXTURE`.
3. **INV-DATA-3:** Zero on-chain settlements and zero Arc broadcasts MUST remain truthfully reported as `0` while AgentVault is undeployed.
4. **INV-DATA-4:** No fake hexadecimal transaction hashes (`0x...`) or fake block numbers may ever be rendered as confirmed blockchain state.
5. **INV-DATA-5:** Persistent system status indicators (Gateway, Arc, Policy, Runtime, Vault) MUST reflect actual health probe results.

## 4. Remediation Plan

The remediation follows a 4-step execution strategy:
1. **Simulation Boundary Layer (`src/lib/data-authority.ts`):** Centralize `DataMode = 'LIVE' | 'SIMULATION' | 'UNAVAILABLE'`, provenance helpers, and safe API wrappers.
2. **API Client De-Mocking:** Update `marketplace.ts`, `clearinghouse.ts`, `clearing_network.ts`, `network.ts`, `treasury.ts`, `control.ts`, `swarms.ts`, and `fabric.ts` so live functions throw or return honest empty states, while deterministic simulation methods remain available for simulation mode.
3. **Component Truthfulness & State Sanitization:** Ensure `/marketplace`, `/economy`, `/network`, `/activity`, `/treasury`, `/transactions`, `/approvals`, `/incidents`, and `GlobalTopBar` render honest live/empty/simulation states without hardcoded mock constants leaking into live mode.
4. **Automated Verification Suite:** Implement automated tests proving all 10 invariants across live, simulation, and empty states.
