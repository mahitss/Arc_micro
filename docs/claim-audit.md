## 1. Methodology & Taxonomy

In accordance with **Rule Zero** ("Do Not Trust Documentation; Verify Against Source Code, Tests, Scripts, Git History, Build Output, and Live Blockchain State"), every quantitative and externally verifiable claim is classified into exactly one of five formal statuses:

1. **`VERIFIED`**: Proven true by automated tests, compiler output, benchmark measurements, or live blockchain queries.
2. **`PARTIALLY VERIFIED`**: Subsystem exists and is largely functional, but specific sub-claims (e.g., universal percentages or external integrations) are narrower or mischaracterized.
3. **`NOT VERIFIED`**: Claimed capability or state cannot be independently confirmed with existing evidence.
4. **`FALSE / OUTDATED`**: Directly contradicted by codebase facts, configuration behavior, or live network state.
5. **`OPERATOR ACTION REQUIRED`**: Code is complete and ready, but external operational prerequisites (e.g., smart contract broadcast, KMS key provisioning, funding) have not been executed.
