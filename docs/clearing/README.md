# AgentPay Autonomous Economic Clearing Network (Task 18)

> **CORE PRINCIPLE**:
> *Agents may create economic obligations. AgentPay determines how those obligations may safely settle.*
>
> **SECOND PRINCIPLE**:
> *Clearing may coordinate value. Clearing may not create financial authority.*

---

## 1. Executive Summary

Task 18 evolves AgentPay's Clearinghouse into a decentralized, network-aware clearing layer capable of coordinating obligations generated by:
- Autonomous agent swarms
- Marketplace contracts
- Milestone deliverables
- Recurring subscriptions
- Cross-tenant work delegations

Crucially, **Clearing does NOT create a second financial ledger or second payment system**. Financial source-of-truth remains strictly consolidated in the canonical Clearinghouse double-entry ledger, Treasury liquidity reserves, PaymentIntent pipeline, and verified Arc blockchain settlement evidence.

## 2. Core Invariants (INV-201 — INV-220)

Machine-checked invariants enforced throughout the clearing lifecycle:

| Invariant | Description | Enforcing Subsystem |
|-----------|-------------|---------------------|
| **INV-201** | Clearing cannot create financial authority. | Service & ClearingClient |
| **INV-202** | Netting cannot create or destroy value ($\sum \text{gross} = \sum \text{net} + \sum \text{savings}$). | NettingEngine |
| **INV-203** | Netting cannot bypass constitutional policy. | SettlementRouter |
| **INV-204** | Netting cannot bypass risk limits. | RiskEvaluator |
| **INV-205** | Netting cannot bypass governance approval. | ApprovalEngine |
| **INV-206** | Netting cannot bypass Treasury liquidity bounds. | TreasuryService |
| **INV-207** | Settled obligations cannot silently mutate. | StateMachine & Immutability |
| **INV-208** | Partial batch execution must explicitly isolate per-obligation states. | BatchExecutor |
| **INV-209** | Ambiguous blockchain settlements cannot be blindly rebroadcast. | SettlementReconciler |
| **INV-210** | Disputed obligations cannot silently settle or be netted. | DisputeRegistry |
| **INV-211** | Expired obligations cannot settle without revalidation. | StateMachine |
| **INV-212** | Recurring obligations require per-occurrence authorization. | DurableRuntime |
| **INV-213** | Cross-tenant obligations and netting pools are strictly isolated. | TenantContext |
| **INV-214** | Counterparty exposure is derived from authoritative obligations. | CounterpartyRegistry |
| **INV-215** | Marketplace state cannot directly mutate the ledger. | MarketplaceClient |
| **INV-216** | Protocol messages cannot directly mutate financial truth. | ProtocolReceiver |
| **INV-217** | Simulator runs cannot mutate persistent clearing state. | SimulationTwin |
| **INV-218** | Read models cannot mutate financial truth. | ControlTower |
| **INV-219** | Unverified blockchain evidence must be marked NOT VERIFIED. | EvidenceAuditor |
| **INV-220** | Netting cannot reduce accounting value incorrectly. | NettingMath |
