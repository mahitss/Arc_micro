# AgentPay Web Control Center

## Overview

The AgentPay Web Control Center (`apps/web`) is a developer-grade infrastructure console designed for operators and developers managing autonomous AI agents, deterministic spending policies, and on-chain Arc USDC settlements.

It provides real-time visibility and control across:
- Registered autonomous agents and their operating statuses.
- Custodial USDC balances held in `AgentVault` smart contracts.
- Deterministic spending policies enforced off-chain by the Rust Policy Engine and on-chain by Solidity rules.
- Payment intents generated by AI agents through their complete lifecycle.
- On-chain transaction execution and settlement on Arc.
- The approved Service Registry.
- Human-in-the-loop payment confirmation approval flows.
- Multi-tier system health across Web, Go Gateway, Rust Policy Engine, Database, and Arc RPC.

## API Client Architecture

The frontend uses a centralized, strongly-typed API client located in [`apps/web/src/lib/api/`](file:///c:/Users/pc/OneDrive/Desktop/Arc%20micro/apps/web/src/lib/api/):

- **[`client.ts`](file:///c:/Users/pc/OneDrive/Desktop/Arc%20micro/apps/web/src/lib/api/client.ts)**:
  - Base URL resolved from `NEXT_PUBLIC_API_URL` or `NEXT_PUBLIC_GATEWAY_URL` (default: `http://localhost:8080`).
  - Request timeouts via `AbortController` (default: 10s).
  - Strongly-typed `ApiError` capturing HTTP status, error codes, and `X-Request-ID` correlation headers.
- **Domain Modules**:
  - `agents.ts`: `fetchAgents()`, `fetchAgent(id)`
  - `intents.ts`: `fetchIntents(statusFilter?)`, `fetchIntent(id)`, `authorizeIntent(id)`, `confirmIntent(id)`
  - `transactions.ts`: `fetchTransactions()`
  - `services.ts`: `fetchServices()`
  - `health.ts`: `fetchSystemHealth()`
  - `demo_fixtures.ts`: Isolated fixtures for **Demo Mode**.

## Security Model

1. **Zero Private Key Exposure in Browser**:
   The frontend never stores, prompts for, or handles private keys, seed phrases, or signing credentials. All blockchain transactions are prepared, signed, and broadcast exclusively by the Go Gateway's isolated execution service.
2. **Untrusted AI Content Handling**:
   AI justification text and metadata are sanitized and rendered as untrusted content. `dangerouslySetInnerHTML` is prohibited.
3. **No Arbitrary Recipient Creation**:
   The frontend cannot formulate arbitrary recipient addresses. The backend Service Registry resolves trusted recipients server-side.
4. **Read-Only Policy & Configuration**:
   Environment-level security settings (`AGENT_AUTO_EXECUTION`, `ENABLE_LIVE_EXECUTION`, `PAYMENT_INTENT_TTL_SECONDS`) are read-only in the UI.

## Error Handling & Demo Mode

### Real Data Invariant
- If the Go Gateway or Arc RPC is unavailable, the UI explicitly shows **"Network unavailable"** with a retry button.
- The UI **never** silently turns an RPC failure or network error into "$0.00" balance or zero metrics.

### Demo Mode
- When backend services are offline during UI development or evaluation, users can toggle **Demo Mode**.
- In Demo Mode, isolated mock fixtures are loaded. All demo entities are explicitly prefixed with `[DEMO]` to prevent any confusion with real on-chain data.
- Demo mode is clearly badged in the UI: `● DEMO MODE ACTIVE`.

## Approval Flow

When `AGENT_AUTO_EXECUTION=false`:
1. The AI generates a payment intent in `CREATED` status.
2. The operator or system triggers authorization via `POST /v1/payment-intents/:id/authorize`.
3. The Rust Policy Engine evaluates limits and returns `ALLOW`.
4. The UI displays: `"Authorization successful — payment requires confirmation."`
5. The operator clicks **Confirm Payment**.
6. An accessible [`ConfirmationDialog`](file:///c:/Users/pc/OneDrive/Desktop/Arc%20micro/apps/web/src/components/ConfirmationDialog.tsx) opens, displaying the Agent, Service, Amount, Recipient, Policy status, and Network.
7. Upon explicit confirmation, the Go Gateway executes the transaction on Arc.
