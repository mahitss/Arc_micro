## 1. Executive Audit Summary

A semantic and visual audit of `apps/web/src/app/control/page.tsx` was conducted. While the visual aesthetic (matte-black, amber accents, green/red status indicators) is high quality, the page currently mixes conflicting provenance states (`LIVE`, `REAL`, `PROJECTED`, `VERIFIED`, `SETTLED`, `ALLOWED`, `SIGNED`) within a runtime that is fundamentally running in **`SIMULATION`** mode with `ENABLE_LIVE_EXECUTION=false` and an undeployed `AgentVault`.

This creates potential cognitive friction for technical judges:
- Top banner states `SIMULATION — NO FUNDS MOVED`, but metric cards right below show `provenance="LIVE"`.
- AI Advisory panel renders red `✗` icons next to `Zero Key Custody (INV-01)` and `Zero Signing Authority (INV-02)`, which makes passing security invariants look like failures.
- Control layer lists `✓ Isolated KMS / HSM Signer`, despite backend repository returning `ErrKMSSignerUnavailable` (failing closed).
- Financial authority pipeline displays `EXECUTION: ALLOWED / Relayer Signed` in green, implying live on-chain signing occurred.
- Treasury metric displays `SETTLED: $1,204.32` directly adjacent to Arc reporting `Real Settlements: 0`.
- Economic timeline is titled `LIVE ECONOMIC TIMELINE` despite operating on deterministic simulation fixtures.

## 3. Canonical Mode & Truth Model

### A. System Mode
$$\text{MODE} = \mathbf{SIMULATION}$$
$$\text{LIVE\_EXECUTION} = \mathbf{DISABLED}$$
$$\text{AGENTVAULT} = \mathbf{NOT\ DEPLOYED\ ON\ MAINNET\ (0x)}$$
$$\text{REAL\ SETTLEMENTS} = \mathbf{0}$$

### B. Authority vs. Execution Separation
A clear semantic distinction must be rendered across all financial cards:
- **Authorization Decision:** Can be `ALLOWED` (deterministic policy verification succeeded).
- **Execution Operation:** Is `SIMULATED / NOT BROADCAST` (no keys touched, no transaction signed, zero funds moved).

### C. Provenance Vocabulary
- `SIMULATED`: Generated by deterministic in-memory simulator or demo VCR.
- `PROJECTED`: Financial estimation based on active envelopes and quotes.
- `VERIFIED`: Independently validated on-chain state (e.g. Arc RPC reachable, Native USDC contract bytecode).
- `NOT DEPLOYED`: Contract compiled locally but not broadcast to mainnet.
- `NOT IMPLEMENTED`: Interface stubbed to fail closed (e.g. KMS).
